# XKeen UI

Лёгкая панель управления для XKeen — обёртки Xray-core / Mihomo (Clash Meta) для роутеров Keenetic. Один самодостаточный бинарь, минимум зависимостей, доступ из локальной сети через браузер.

## Установка

Стабильная версия:

```sh
curl -fsSL https://raw.githubusercontent.com/nvorobev/XKeenUI/main/setup.sh | sh
```

Бета:

```sh
curl -fsSL https://raw.githubusercontent.com/nvorobev/XKeenUI/main/setup.sh | sh -s -- beta
```

Скрипт интерактивный, предлагает меню:

1. Установить / переустановить
2. Обновить
3. Удалить

При установке скрипт задаёт три вопроса; Enter оставляет значение по умолчанию:

- **Порт панели** — по умолчанию 1000, при переустановке подставляется прежний.
- **Пароль admin** — вводится дважды и не отображается на экране. Enter оставляет текущий пароль, а на новой установке — `admin`.
- **Блокировать трафик мимо прокси?** — спрашивается, если XKeen работает через политику доступа. Подробнее — в разделе «Защита трафика».

Установить без вопросов, например из своего скрипта:

```sh
read -rs XKEEN_UI_PASSWORD; export XKEEN_UI_PASSWORD
curl -fsSL https://raw.githubusercontent.com/nvorobev/XKeenUI/main/setup.sh | sh -s -- install --port 8080 --guard -y
```

| Параметр | Что делает |
| --- | --- |
| `install`, `update`, `uninstall` | действие без меню |
| `--port N` | порт панели |
| `--guard` / `--no-guard` | включить или выключить блокировку трафика мимо прокси |
| `-y`, `--yes` | ничего не спрашивать: чего нет в параметрах, остаётся как есть |
| `beta` | ставить бета-версию |
| `--help` | справка |

Пароль передаётся через переменную окружения `XKEEN_UI_PASSWORD`, а не параметром, чтобы он не остался в истории команд.

Архитектура определяется автоматически. Бинарник скачивается во временный каталог и проверяется по SHA-256; при ошибке загрузки прежняя версия остаётся на месте.

## Доступ

После установки панель доступна по адресу `http://<router-ip>:1000`. Порт по умолчанию — **1000**, меняется в init-скрипте `/opt/etc/init.d/S99xkeen-ui` через `ARGS="-p <PORT>"`.

На новой установке вход включён: логин **admin**, пароль **admin**. В разделе
**Пользователи** можно изменить пароль и добавить другие учётные записи.
Учётную запись admin нельзя удалить или переименовать. При обновлении существующей
панели её пароль и настройка включения входа сохраняются.

Хеширование — Argon2. Защита от перебора: 5 неуспешных попыток с одного адреса для одной учётной записи → блокировка на 60 секунд. Сброс пароля: `xkeen-ui reset-password`.

## Разделы панели

Слева — меню, сверху — состояние службы XKeen с кнопками запуска, остановки и перезапуска.

- **Обзор** — плитки (выход, скорость, устройства в XKeen, защита трафика) и карточки: подключение с выбором сервера и режимом «Авто / Вручную», график трафика за 10 минут, устройства с переключателем политики XKeen, роутер и служба, последние ошибки журнала. Карточки перетаскиваются за значок ⋮⋮, порядок запоминается в браузере. Резервные копии, ядра, обновление, пользователи и настройки — в группе «Обслуживание» меню слева.
- **Серверы** (только для ядра Xray) — все серверы из конфигов и добавленные по ссылке, отметка «в пуле» для автопереключения, кнопка «Сделать активным». Подробнее — [Серверы Xray](xray-servers.md).
- **Конфигурация** — редактор конфигов с подсветкой, автодополнением, проверкой и историей изменений; конструктор маршрутов Xray, импорт AmneziaWG, шаблоны, скан геофайлов и проверка маршрута. Для Mihomo здесь же вкладки «Группы», «Соединения» и «DNS» (через Clash API).
- **Журнал** — логи в реальном времени с фильтрацией.
- **Обслуживание** — резервные копии, выбор и обновление ядер Xray / Mihomo, настройки панели.

## Конструктор маршрутов Xray

Откройте **Конфигурация → 05_routing.json → Конструктор маршрутов**. Кнопка доступна в JSON и визуальном режиме. Слева уже выбраны текущие правила, справа открыт полный текущий конфиг. При изменении настроек справа сразу появляется будущий конфиг; кнопка сравнения возвращает исходный вид. Рабочие файлы при редактировании не меняются.

1. Выберите быстрый сценарий: **Весь трафик через VPN**, **VPN кроме РФ** или **Только заблокированные**. Либо настройте три категории вручную: **Блокировка**, **VPN**, **Прямое подключение**.
2. В категориях доступны переключатели рекламы, QUIC, Discord, локальных сетей и торрентов, а также отдельные разделы портов TCP/UDP, IP/подсетей, доменов и GeoIP/GeoSite. Можно выбирать готовые списки или вводить свои. Недоступные в установленных базах категории отключены с объяснением причины.
3. Задайте порядок категорий стрелками. Xray проверяет правила сверху вниз до первого совпадения. Переключатель «Всё через VPN»/«Всё напрямую»/«Блокировать остальное» задаёт единственное последнее правило для остального трафика.
4. Справа сразу меняется будущий конфиг. Вкладка **Карта** показывает устройство, роутер, провайдера, VPN-сервер и интернет со стрелками; выбор правила подсвечивает его путь. Кнопка **На весь экран** раскрывает карту с крупными подписями; **Свернуть карту** или Escape возвращает в конструктор. Развилка маршрутов находится у роутера, провайдер показан как транспорт. Проверка конкретного адреса подсвечивает рассчитанный маршрут. Вкладка **Таблица** показывает условия и действие каждой строки. **Сравнить с текущим** возвращает исходный просмотр. Проверка адреса объясняет, какое правило сработает, с валидацией полного черновика настоящим ядром.
5. Нажмите **Применить** либо **Передать в редактор** для дальнейшего редактирования. **Копировать** и **Скачать** экспортируют JSON маршрутов, **Сбросить** очищает настройки категорий. Служебные API-правила, балансировщики и остальные разделы файла сохраняются.

GeoSite/GeoIP требуют соответствующих баз и категорий на роутере. **Отключать пул для изменения маршрутов не нужно**: панель пересоздаёт `07_pool.json` из новых исходных правил, проверяет полный набор Xray и сохраняет оба конфига и настройки пула одной транзакцией. Выбранный сервер, состав пула и автопереключение сохраняются. При ошибке запуска восстанавливаются прежние файлы и рабочая конфигурация. При работающем пуле кнопка сохранения маршрутов также применяет их штатным перезапуском XKeen. В исходных правилах выбирайте обычный outbound: перенаправление через пул панель добавляет автоматически.

Если правила со сложными условиями нельзя безопасно разложить по категориям, конструктор сохраняет весь исходный список в прежнем порядке и показывает уведомление. Новые правила добавляются после него. Условия одного правила объединяются через «И».

При `AsIs` домены не разрешаются в IP для правил IP. При `IPOnDemand` DNS используется при проверке IP-условий. Если задано явное последнее правило для всего остального TCP/UDP-трафика, при `IPIfNonMatch` до второго прохода DNS дело не дойдёт. При сохранении исходного выхода без нового завершающего правила второй проход остаётся возможным.

## Защита трафика

**Настройки панели → Защита трафика → Включить защиту трафика.** Переключатель включает защиту для устройств политики доступа XKeen. Поле «Когда блокировать интернет» выбирает режим; при выключенной защите список недоступен, выбранный режим сохраняется.

В режиме **«Если не работает XKeen»** устройства из политики XKeen ходят на проксируемые порты (по умолчанию 80 и 443) через Xray. Если XKeen остановлен, ядро упало или роутер ещё загружается, перехвата нет, и такой трафик может уходить в интернет напрямую через провайдера. Защита блокирует этот обход. Если ядро работает, но VPN-сервер недоступен, прямые маршруты (`direct`) остаются доступны: этот режим не проверяет VPN-сервер.

Опция ставит хук `/opt/etc/ndm/netfilter.d/90-xkeen-ui-guard.sh`. Метку политики, порты и исключения он берёт из хука XKeen (`proxy.sh`), поэтому всегда совпадает с тем, что XKeen перехватывает. Не затрагивает остальные порты устройств, устройства вне политики XKeen, локальную сеть, исключения XKeen и запросы самого роутера. Пока прокси работает, правило ничего не блокирует. Чтобы напрямую не уходили и другие порты, очистите список проксируемых портов в XKeen.

Не снимайте в политике XKeen галку подключения к провайдеру: через неё работает DNS устройств этой политики. Включать и выключать опцию может только admin; при удалении панели хук удаляется.

Режим **«Если недоступен VPN (включая direct)»** проверяет HTTPS/HTTP-соединение через выбранный VPN и при неудаче блокирует интернет устройств политики XKeen, включая `direct`, любые порты и IPv6. Блокируются новые запросы и передача данных по уже открытым соединениям в обоих направлениях, в том числе ответы прозрачного прокси. Локальная сеть и доступ к панели сохраняются; публичные исключения XKeen в этом режиме не обходят блокировку. Для Xray проверяется активный сервер пула или текущее самостоятельное подключение. Для Mihomo нужно выбрать сервер или группу в поле «Проверяемый VPN»; выбор `DIRECT` не считается доступным VPN.

Проверки выполняются каждые 5 секунд после завершения предыдущей (таймаут запроса — до 5 секунд, запуск проверки Xray — дополнительно до 10 секунд). Блокировка появляется после неуспешной проверки, а не мгновенно в момент отказа сервера. При включении режима и после перезагрузки интернет закрыт до первой успешной проверки; после восстановления VPN он открывается автоматически. Независимый watchdog закрывает доступ при завершении панели или истечении свежего успешного результата. Запросы самого роутера остаются доступны для проверки и восстановления VPN. Отключить защиту без панели можно командой `xkeen-ui traffic-guard off`.

Защита охватывает только устройства, назначенные в политику XKeen. Если устройство сменило MAC или его перевели в другую политику, режим его не блокирует.

## Команды

| Команда | Описание |
|----------|----------|
| `create-init` | Создать init-скрипт |
| `start` | Запустить сервис (требуется init-скрипт) |
| `stop` | Остановить сервис (требуется init-скрипт) |
| `restart` | Перезапустить сервис (требуется init-скрипт) |
| `status` | Показать статус сервиса (требуется init-скрипт) |
| `reset-password` | Сбросить пароль: вход снова `admin` / `admin`; работающая панель перезапускается |
| `set-password` | Задать пароль admin и включить вход: из `XKEEN_UI_PASSWORD` или первой строки stdin |
| `traffic-guard on\|off` | Включить или выключить блокировку трафика мимо прокси |
| `setup` | Запустить установочный скрипт |
| `disable-xray-servers` | Отключить управление серверами Xray и вернуть исходные `routing`/`api` |

| Опция | Описание |
|--------|----------|
| `-p, --port <PORT>` | Запуск сервиса с указанием порта (по умолчанию: `1000`) |
| `-d, --debug` | Режим отладки |
| `-h, --help` | Показать список доступных команд |

## Автозапуск панели

Установщик создаёт исполняемый `/opt/etc/init.d/S99xkeen-ui` с `ENABLED=yes`. При ручном запуске панель также восстанавливает отсутствующий init-скрипт и права выполнения, сохраняя существующий порт и явное `ENABLED=no`. Сам автозапуск выполняет Entware при загрузке роутера.

В `/opt/var/log/xkeen-ui.log` строки `[INIT] action=...`, `Starting XKeen UI` и `HTTP listener ready` позволяют различить вызов init, старт процесса и готовность HTTP. Обычный SIGTERM при остановке записывается как `INFO`. Если после перезагрузки нет даже `[INIT]`, проверяйте запуск Entware и доступность `/opt` при загрузке; если init вызван — смотрите следующие строки журнала. Без журнала конкретной загрузки причину сбоя определить нельзя.
