# Серверы Xray

Раздел **Серверы** в меню слева доступен, когда активно ядро Xray. Несохранённые
изменения в разделе «Конфигурация» нужно сначала сохранить или отменить.

## Список серверов

На странице один список **«Все серверы»**: outbound'ы из текущих JSON/JSONC-конфигов
и серверы, добавленные по ссылке. Сверху — активный сервер, через который сейчас идёт
трафик. Список можно отфильтровать («Все», «В пуле», «Доступны») и отсортировать
(по задержке, имени или источнику).

- **Галочка «в пуле»** — сервер проверяется в фоне и может стать активным при сбое.
  При включённом пуле активный сервер всегда остаётся его участником.
- **«Сделать активным»** — проверяет доступность сервера и переключает на него трафик
  с перезапуском Xray штатной командой `xkeen -restart`, чтобы открытые соединения
  также перешли на выбранный сервер. Для сервера вне пула заменяет текущее
  подключение; создавать пул
  для этого не нужно. Если пул уже включён, панель предложит отключить его.
  Если проверка не прошла, прежний выбор сохраняется. Выбор
  записывается на диск и переживает перезапуск ядра и панели.
- **«Добавить по ссылке»** — ссылка подключения или JSON одного самостоятельного
  outbound; имя сервера задаётся отдельно. Сервер сразу сохраняется на роутере,
  независимо от включения пула. Галочкой его можно добавить в пул, а удалить — через
  меню строки после исключения из работающего пула.
- **«Проверить все»** — разовая проверка задержки всех серверов из списка.

## Включение пула

1. Отметьте галочкой серверы для пула — outbound, через который сейчас идёт трафик,
   автоматически станет активным. Если подходящих outbound несколько, в блоке
   «Автопереключение» выберите, какой трафик переключать.
2. При желании нажмите «Сделать активным» у другого сервера пула.
3. Нажмите **«Включить пул»** внизу страницы. Панель проверит полный набор конфигов,
   сохранит исходное содержимое и перезапустит Xray. При ошибке запуска прежние файлы
   и прежняя конфигурация возвращаются.

Дальнейшие изменения копятся в черновике и применяются кнопкой **«Сохранить и
применить»**. Xray перезапускается, только если меняется набор серверов; панель
заранее показывает, будет ли перезапуск.

Меняются только правила, направленные непосредственно на выбранный outbound, и выход
по умолчанию, если он использовал этот outbound. Прямые, блокирующие правила и другие
балансеры сохраняются. Управление уже существующим балансером не поддерживается.
При включении эффективные `routing` и `api` копируются в `07_pool.json`.
Исходные файлы, их форматирование и комментарии остаются нетронутыми. При обновлении
старой версии панель восстанавливает ранее перенесённые разделы из сохранённой копии
и удаляет прежний `zz-xkeen-ui-servers-tail.json` в одной операции с возможностью отката.

## Автопереключение

Проверки выполняет панель на роутере; браузер можно закрыть.

- По умолчанию серверы пула проверяются раз в **60 секунд**, таймаут — **5000 мс**,
  порог — **3 неудачные проверки подряд**, адрес проверки — `https://yahoo.com`.
  Всё меняется в блоке «Автопереключение» → «Параметры».
- Проверяется HTTP(S)-запрос через каждый сервер, а не ICMP. Интервал отсчитывается
  после завершения предыдущей проверки, проверки не накладываются друг на друга.
- Пока активный сервер отвечает, он остаётся активным независимо от задержек остальных.
- После подтверждённого отказа выбирается сервер с минимальной задержкой в свежей
  проверке. Затем панель держится уже за новый сервер до его отказа.
- Если недоступны все, выбор сохраняется и проверки продолжаются.
- Установленные соединения не переносятся между серверами: новый выбор применяется
  к новым TCP/UDP-сессиям.
- Если автопереключение выключено, фоновых проверок нет; проверить активный сервер
  можно вручную на странице «Обзор».

Интервал задаётся в миллисекундах: от 1000 до 3 600 000 мс (минимум 1 секунда). Это пауза после
завершения предыдущей проверки, поэтому её длительность также влияет на частоту.
Проверки не перекрываются. Сохранённые ранее значения в секундах переводятся в
миллисекунды автоматически.

## Хранение и восстановление

- Настройки пула и исходное содержимое конфигов: `/opt/etc/xkeen/xray-servers.json`.
- Список сохранённых серверов: `/opt/etc/xkeen/xray-server-library.json`. Он сохраняется
  при отключении пула. Изменения сервера записываются сразу; для работающего пула
  применяются кнопкой **«Сохранить и применить»**.
- Управляемый конфиг: `/opt/etc/xray/configs/07_pool.json`.
  Не редактируйте его вручную: при обнаружении изменения переключение останавливается.
- Журнал незавершённой операции: `/opt/etc/xkeen/xray-servers-transaction.json`.
  При перезапуске панели или повторном сохранении, переключении либо отключении пула
  незавершённые изменения откатываются. После успешного отката файлов журнал удаляется,
  даже если запуск прежнего Xray не подтверждён; ошибку запуска панель сообщает отдельно.
  Изменённые извне файлы не перезаписываются автоматически; журнал остаётся для
  ручного восстановления.
- Исходные файлы, включая `05_routing.json`, при включении пула не изменяются.
  Управляемый `07_pool.json` содержит копию маршрутизации для работы пула и отображается
  в «Конфигурации» после `06` только для чтения.
  Для изменения маршрутизации сначала отключите пул; при следующем включении
  он использует актуальные правила. Удаление и переименование файла пула из панели запрещены.
- **«Отключить управление серверами…»** (внизу блока «Автопереключение») возвращает
  исходные `routing`/`api`, удаляет управляемый конфиг и настройки пула и перезапускает
  Xray, если он был запущен. Работает и при остановленном Xray, и при испорченном
  управляемом файле. Правки, сделанные в конфигах после включения, сохраняются.
- При удалении панели через `setup.sh` то же восстановление выполняется командой
  `xkeen-ui disable-xray-servers`; при ошибке удаление останавливается.

## Ограничения

- API Xray слушает только loopback: по умолчанию `127.0.0.1:10085`. Если уже настроен
  локальный `api.listen`, сохраняется его адрес и прочие API-сервисы.
- Нужна современная версия Xray с `api bo`, `api bi --json` и `RoutingService`.
- Серверы с цепочками `proxySettings` / `dialerProxy` не поддерживаются.
- В пуле — не больше 32 серверов.
